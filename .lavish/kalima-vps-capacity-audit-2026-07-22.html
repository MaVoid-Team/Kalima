Prioritized execution plan

  1. Secure SSH immediately. Add and verify key-based access first, then rotate the disclosed password and disable root password login.
  2. Add observability before the next spike. Retain at least 30 days and alert on CPU saturation/steal, load per core, memory pressure, swap-in/out, disk latency, 5xx rate, p95 latency, DB connections, slow queries, Redis evictions, and queue depth.
  3. Upgrade or separate compute. A 2-vCPU shared host has insufficient headroom for this service count. Separate production from dev and unrelated apps, or move to dedicated 4-8 vCPUs.
  4. Apply container guardrails. Reserve production database/backend resources and cap development, Coolify realtime, and auxiliary services.
  5. Move media off the application host. Use S3-compatible storage plus CDN and signed private URLs. This reduces origin bandwidth, disk growth, and backup size.
  6. Clean only after backup validation. Candidate recovery includes npm cache, browser tooling caches, obsolete backup aliases, unused Docker volumes (539 MB reported), and legacy web trees. Never prune production uploads or database volumes.
  7. Optimize application traffic. Reduce purchases/notification polling, fix expired JWT socket reconnect loops, add caching, and profile the admin store-stat query.
  8. Slim backend images. Each Kalima backend image is 970 MB. Use a multi-stage build and production-only dependencies.
